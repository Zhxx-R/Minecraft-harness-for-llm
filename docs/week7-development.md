# Week 7 Development Document

## Goal

Week 7 implements the first database-backed skill evolution MVP. The skill library is authoritative in SQL; Markdown files are only review/export snapshots. A skill is a structured harness action sequence, not raw Mineflayer JavaScript.

## Delivered Changes

- Extended `SkillSpec`:
  - `validation`
  - `source_run_id`
  - `source_step_range`
  - `task_scope`
  - `dependencies`
  - `metrics`
- Updated `skill.schema.json` and representative schema validation payloads.
- Replaced the placeholder `SkillLibrary` with a database-backed implementation.
- Added skill lifecycle operations:
  - `search(query, scope, limit)`
  - `get(name, version)`
  - `create_candidate(run_id)`
  - `promote(candidate)`
  - `deprecate(skill_id, version, reason)`
  - `export_markdown(skill_id, version)`
- Added database row-lock promotion semantics through SQLAlchemy `with_for_update`.
- Added trajectory events for skill lifecycle actions when a source run exists:
  - `skill_candidate_created`
  - `skill_promoted`
  - `skill_deprecated`
  - `skill_exported`
  - optional `skill_read`
  - optional `skill_search`
- Added multi-level deterministic skill retrieval:
  - exact trigger/canonical id match
  - task tag/scope match
  - action-scope match
  - dependency match
  - lexical fallback over name and description
- Integrated promoted skill summaries into `ContextManager` using progressive disclosure. The prompt receives summaries and action types, not full action plans.

## Storage Model

The existing `skills` table remains the canonical store:

```text
skills.name
skills.version
skills.status
skills.spec
skills.source_run_id
```

The expanded fields live inside `skills.spec`, so Week 7 does not require a database migration. This keeps compatibility with the Week 4 persistence migration while still supporting richer skill metadata.

Markdown exports are generated by `SkillLibrary.export_markdown(...)` and are not read as runtime source of truth.

## Candidate Creation

`create_candidate(run_id)` reads a completed persisted run:

1. Loads `RunRecord`.
2. Loads successful `StepRecord` rows where `action_result.ok == true`.
3. Converts step actions into a structured `action_plan`.
4. Extracts triggers, task scope, dependencies, preconditions, and source step range.
5. Saves a draft `SkillRecord`.
6. Records `skill_candidate_created` on the source run trajectory.

This is the Week 7 MVP version of the policy. The full failure-threshold policy (`same task failed >= 3 times, later success creates a candidate`) can be added on top of the same `create_candidate` method when training history is broader.

## Retrieval

Search defaults to `promoted` skills only:

```python
await library.search(
    "collect oak_log for harvest",
    scope=SkillSearchScope(
        task_tags=("minecraft:harvest",),
        canonical_ids=("oak_log",),
        allowed_actions=("mine_block",),
    ),
)
```

This supports the Week 10 progressive disclosure direction: context first gets skill summaries; full action plans should be loaded only when `execute_skill` or an explicit planner step selects a skill.

## Current Boundary

- `execute_skill` is not implemented yet. Week 7 can create, promote, search, and export skills; execution reuse comes next.
- Failure-threshold candidate scheduling is not automatic yet. The library supports candidate creation from a successful run; training orchestration will decide when to call it.
- Code skills remain out of scope. Week 7 skills are structured action sequences only.
